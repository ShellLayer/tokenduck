# 使用指南

## 安装与操作

从 [Releases](https://github.com/ShellLayer/tokenduck/releases/latest) 下载 ZIP，解压后运行 `TokenDuck.exe`。建议先放到固定目录，再开启右键菜单中的“开机启动”。不需要管理员权限或 Python。

这是便携版，无需安装包。程序已经运行时，再次双击会打开现有实例的“账户与登录”窗口，便于确认运行状态和管理连接。开机启动保持后台运行。

额度始终显示。右键额度区域即可查看订阅详情，并管理连接、显示、自启与退出。菜单顶部按平台列出总额度、套餐、到期和连接异常，Kimi 总额度优先展示。右键“立即刷新”可手动更新，定时刷新照常运行。鼠标经过和左键点击不触发额外操作。

在右键“显示与刷新设置…”的“额度显示方式”中，点击**剩余额度 / 已用额度**两个按钮之一，保存后同时应用于任务栏与右键详情。百分比、进度条和可换算的额度数值保持一致，设置在重启后保留。任务栏只显示平台名，设置和菜单中的“剩余 / 已用”标明当前口径。仅提供余额而没有总量的额外点数仍单独标为余额。

5 小时与周额度持续显示在任务栏。补充详情集中在右键菜单，每次打开时使用当前读数。信息行用于阅读；其下保留刷新、账户、显示、自启等操作。菜单或设置窗口打开期间，额度区域暂停内容重绘、字体调整和位置调整，关闭后恢复待处理更新。未变化的字体布局不会反复设置，以免触发 Windows 菜单重排。

额度区域直接嵌入 Windows 主任务栏。点击任务栏时，额度会随任务栏一起显示，取消了旧版浮动窗口的层级恢复机制。重绘使用双缓冲，后台数据通过界面队列更新；系统重建任务栏时会重新建立额度区域。

Codex 的“订阅到期（登录记录）”来自当前账号、用户和套餐匹配的官方本机登录信息，日期按本机时区显示。它是登录时记录的订阅有效期，续费后可能延迟更新；记录中的日期已过时显示“待更新”，没有该字段时显示“暂未提供”。不使用登录令牌过期时间或额度重置时间推算订阅到期日，也不修改或续期 Codex 的登录凭证。

月总额度提供百分比、实际数量和重置时间，同步遵循剩余／已用设置。Kimi Code 的消耗标为月总额度的来源，不作为另一份独立额度。旧读数标注异常和最后成功日期，较长内容用省略号收尾；完整连接状态可在“账户与登录…”中查看。

GLM / ZCode 的右键详情另列 5 小时和每周额度，例如“每周额度：剩余 57,374 / 60,000 · 96%”。具体数值保留完整数字，以逗号分组；切换到已用模式后显示已用数值和总额度。仅在接口提供具体计数或能由总量与另一项计数换算时展示，不使用四舍五入后的百分比反推数量。

GLM 的 5 小时积分按每笔消耗在 5 小时后动态恢复，不能仅凭刷新时刻推算统一的到期点（[BigModel 规则](https://docs.bigmodel.cn/cn/coding-plan/overview)、[Z.ai 规则](https://docs.z.ai/devpack/overview)）。接口未提供下一次恢复时间时，满额显示“已满”（已用模式为“未用”），有消耗显示“滚动”；缺少准确时间的旧读数显示“待刷新”；恢复时间已到、尚未刷新时也显示“待刷新”。只有接口给出准确时间时才显示恢复倒计时，并标注“恢复于”；周额度保留服务端返回的重置时间。

两列通常对应 5 小时与周额度，只有月额度时也会显示。默认剩余模式中 `100%` 为未使用、`0%` 为耗尽；已用模式则相反。未提供的额度不推算为满额或零用量。请求失败时保留上次读数，置灰并添加 `*`。重启后的缓存同样先置灰，等刷新成功再恢复。健康额度按平台使用 Codex 绿、Kimi 蓝、GLM 紫，深浅主题自动使用相应色值；真实余量不超过 25% 时使用橙色，不超过 10% 时使用红色。告警颜色始终根据真实余量判断。

## 连接账号

**Codex**：读取 `CODEX_HOME` 指定目录或 `~/.codex/auth.json` 中的官方登录。账户页的“官方登录”调用已安装的官方 Codex 登录流程，您在官方网页完成验证。此操作会更新官方客户端的本机登录；工具不自行续期其凭证。

**Kimi**：优先读取桌面端的结构化登录，尝试建立属于 TokenDuck 的独立会话。独立会话可使用自己的续期令牌，不要求浏览器持续打开。无法建立独立会话时，仅借用短期访问令牌，过期后可能需要重新打开官方客户端登录。

Kimi 账号保持绑定。换号时先在 Kimi 登录目标账号，再主动选择“使用本机 Kimi 登录”；验证新账号额度成功后才替换原绑定。浏览器连接默认关闭，只有主动选择后才启用；不复制浏览器数据库，也不导入或消费借用来源的续期令牌。也可加密保存已有 Kimi Code key。

**ZCode / GLM Coding Plan**：读取本机 ZCode 的套餐配置或凭证；也可添加已有套餐 key，并明确选择 BigModel 或 Z.ai。不会自动创建云端 key 或修改 ZCode 的登录文件。

## 配置与升级

新安装的数据目录为 `%APPDATA%\tokenduck`：

| 文件 | 内容 |
| --- | --- |
| `accounts.dat` | Windows 当前用户加密的本工具凭证 |
| `config.json` | 字号、颜色、位置、刷新间隔等设置 |
| `usage_cache.json` | 最近额度与成功时间，不含登录令牌 |
| `self_check.json` | 可选的离线自检结果 |
| `crash.log` | 意外退出或启动失败的排查记录 |
| `quota_diagnostics.json` | 手动运行打包版 `--once` 时生成的额度诊断，分享前需检查 |

从早期 CodexBar 版本升级时，如果新目录没有配置或账号文件，会继续使用 `%APPDATA%\codexbar` 中已有的数据，不搬移或复制凭证。已有 `codexbar.vbs` 自启项会原地更新为当前运行文件的路径；新安装使用 `tokenduck.vbs`。旧加密格式和单实例标记保留，避免更名前后重复运行。

配置颜色为 `#RRGGBB`，留空跟随任务栏主题。无效值回退默认设置。程序目录中的旧配置仅在首次迁移时导入，其中的手动 key 会转入加密存储。

更新时先右键退出，替换程序后启动。已经开启自启时，正常启动会更新自启路径；移动目录后请重新运行一次。

## 卸载

取消“开机启动”，右键退出，然后删除解压的程序目录。需要清除本工具数据时，再删除上述属于 TokenDuck 的数据文件。旧 `%APPDATA%\codexbar` 可能同时含有其他程序的数据，请勿不加区分地删除整个旧目录。

卸载不会退出官方 Codex、Kimi 或 ZCode 客户端。若希望撤销已创建的 Kimi 独立会话，请在官方账号的设备或会话管理中处理。

## 常见情况

- **看不到额度区域**：检查是否已经运行，调整横向位置与字号；当前优先支持 Windows 11 的底部主任务栏。
- **双击后没有反应或程序退出**：再次运行应打开账户管理窗口。若使用 0.3.10，请升级到最新版本；该版本出现过异常退出，已停止作为正式最新版提供。
- **灰色数字和 `*`**：右键查看失败原因，检查官方客户端是否登录；必要时在账户页重新连接。
- **换电脑后无法解密**：加密依赖 Windows 当前用户环境，请重新连接账号，不要复制旧凭证文件到另一台电脑。
- **启动时提示发布者未知**：当前发行版尚未签名，可使用 Release 的校验文件核对下载内容。
